**FileGeneratorUtils.java**

**Purpose:**
This class provides a suite of powerful utilities for dynamically generating document files (`.docx` and `.pdf`) from templates and for handling image uploads. It integrates several libraries to create a seamless workflow from data to a final file format.

**How it works:**
The class is a Spring `@Component` and relies on an injected `CloudinaryUtils` bean for image handling.

- **Core Libraries Used:**
  - **XDocReport:** A Java library used to merge a template (in this case, a `.docx` file) with data. It uses templating engines like Freemarker to find and replace placeholders in the document.
  - **Apache POI:** A popular Java library for working with Microsoft Office documents. Here, it's used to read and parse the generated `.docx` file.
  - **POI PDF Converter:** An extension for Apache POI that enables the conversion of a `.docx` document object into a `.pdf` file.

- **`generateWordFromTemplate(String templatePath, Map<String, Object> data)` Method:**
  - This is the foundational method for document generation.
  - It loads a `.docx` template file from the application's resources using `templatePath`.
  - It uses the **XDocReport** library to treat the template as a Freemarker template.
  - It creates a `context` and populates it with the key-value pairs from the input `data` map. The keys in the map correspond to placeholders in the `.docx` template (e.g., `${name}`, `${date}`).
  - The `report.process()` method performs the merge operation, replacing all placeholders with the provided data.
  - The final merged document is saved as a temporary `.docx` file on the server.
  - It returns the `File` object pointing to this newly created Word document.

- **`convertDocxToPdf(File wordFile)` Method:**
  - This method takes a `.docx` file (typically one generated by the method above).
  - It uses **Apache POI** (`XWPFDocument`) to read the Word file into memory.
  - It then uses the **PdfConverter** instance to transform the in-memory document into a PDF.
  - The output is saved to a new temporary `.pdf` file.
  - It returns the `File` object for the generated PDF.

- **`exportPdfBase64(String templatePath, Map<String, Object> data)` Method:**
  - This is a high-level workflow method that combines the above functionalities.
  - It first calls `generateWordFromTemplate` to create the `.docx` file.
  - It then passes the result to `convertDocxToPdf` to get the `.pdf` file.
  - It reads all bytes from the final `.pdf` file.
  - It encodes these bytes into a **Base64** string, which is a common way to transmit file data over text-based protocols like JSON/HTTP.
  - Finally, it performs cleanup by deleting the temporary `.docx` and `.pdf` files from the server's disk using the `safeDelete` helper.
  - It returns the Base64-encoded string representation of the PDF.

- **`generateWordFromTemplateReturnBase64(...)` Method:**
  - A variation of the above that stops after generating the `.docx` file. It encodes the Word document (not a PDF) into a Base64 string and returns it.

- **`saveImageFromBase64(String base64String, String fileName)` Method:**
  - This utility handles image data provided as a Base64 string.
  - It decodes the Base64 string back into its raw image bytes.
  - It saves these bytes to a temporary local file.
  - It then uses the autowired `cloudinaryUtils` to **upload the image to Cloudinary**.
  - After a successful upload, it deletes the temporary local image file.
  - It returns the upload details from Cloudinary (likely the public ID and secure URL).

**Usage:**
This class is essential for any feature that requires creating downloadable or viewable documents based on dynamic data. Common use cases include:
- Generating reports (e.g., end-of-quarter sales reports).
- Creating invoices or receipts.
- Exporting user data in a formatted document.
- Generating certificates or official letters.
The image handling part is useful for features where users can upload images (e.g., profile pictures, content images) which are then stored in a cloud service like Cloudinary.
